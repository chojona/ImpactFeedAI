## Root causes and corrections

### Calendar and temporal bounds

A release between 13:00 and 16:00 ET on 2022-07-01, 2022-12-23 or
2026-07-02 was incorrectly assigned to the next canonical SPY session. The
same day's final equity close was then treated as a prior-session price
available at 13:00, even though the actual session completed at 16:00. With a
14:00 release this admits a price realized two hours later. A required missing
prior-session bar could be concealed by that incorrect selection.

Independently checked official [NYSE 2022–2024
hours](https://ir.theice.com/press/news-details/2021/NYSE-Group-Announces-2022-2023-and-2024-Holiday-and-Early-Closings-Calendar/default.aspx),
[2025–2027 hours](https://ir.theice.com/press/news-details/2024/NYSE-Group-Announces-2025-2026-and-2027-Holiday-and-Early-Closings-Calendar/default.aspx)
and [2026–2028
hours](https://ir.theice.com/press/news-details/2025/NYSE-Group-Announces-2026-2027-and-2028-Holiday-and-Early-Closings-Calendar/default.aspx).
Removed only those three false half-days, preserving all 11 source-listed
half-days in the supported 2022–2026 range. An additional reproduced guard
issue refused a covered release merely because an earlier, already completed
session predated that range; ambiguity is now evaluated against the candidate
session's actual date and bounds.

Daily bar stamps identify source bars. The modeled economic close identifies
completion of the interval whose closing price is used. Actual provider
availability/delivery can be later and is **not proven by interval completion**.
The engine now accepts optional independently evidenced `availableAt`, rejects
contradictory/invalid evidence and requires it strictly before release when
supplied. With no such evidence, completion is only a lower bound, and the
output is not point-in-time certified. Invalid release/anchor timestamps fail
closed. A missing fixed prior-session anchor still refuses the window; it never
borrows a later price. Intraday anchors use open values, not a completed bar's
close/high/low; a known delayed open cannot anchor the release.

The calculation contract §6.3 requires a historical calendar version change.
`COMPUTED_REACTION_CALCULATION_VERSION=4` governs the additive writer;
`CURRENT_REACTION_CALCULATION_VERSION=3` retains reads until acceptance.
The writer also applies the shared full timing-eligibility predicate, including
nonblank provenance, after its database candidate filter.

### Verification completeness

The old verifier visited only events with stored rows, and skipped missing
release timestamps or failed reference fetches without failing the command.
It could not detect an event whose entire measurement set was absent.

The replacement constructs expected opportunities from **all source events**,
the timing policy, the 12-instrument universe and four fixed measures. It tests
uniqueness/extra combinations and does not derive expectation from observed
rows. It independently re-derives release-session origin before checking offsets,
validates timestamp/day/basis/price/return invariants, enforces intraday anchor
age and endpoint target/slip, checks source bar/day mapping, and fails zero or
incomplete verification. Session endpoints remain daily **closes**, even when
the daily bar's opening stamp precedes release.

A generic 17:00 futures close is not an authoritative contract/holiday/settlement
calendar. Strict qualification flags those session rows instead of certifying
that assumption. Historical missing first-hour rows remain unresolved without
archived evidence; current provider retention does not prove historical absence.
Expected opportunities therefore differ from proven measurable windows.
`legitimatelyUnavailable=0` means no absence has been justified with the available
historical evidence, not that all 960 windows must have existed.

Pure checks live in `measurementVerification.ts` and source-event coverage in
`measurementCoverage.ts`; the CLI captures/replays evidence and exits nonzero
on failures. Successful arithmetic is not source-price reconciliation or PIT
certification. The report explicitly states that limitation.

### Historical macro actuals

The schema stores one current shaped actual per event/metric, without immutable
revision, publication or availability history. Curated FRED fallback to latest
history loses its vintage distinction; bulk FRED/BLS history and `:initial:`
natural keys cannot establish first prints.

The [historical provenance policy](../historical-provenance-policy.md) defines
initial, revised, current-database and unresolved values separately from
availability quality; reconstruction versus system replay; strict cutoff,
first-print/consensus requirements; and an additive append-only observation,
evidence and conflict model compatible with Phase 1. The pure eligibility
boundary rejects legacy values for PIT use. It verifies necessary metadata
conditions; independent source review must establish the evidence's truth.
There is no deployed vintage model or claim that missing evidence was recovered.
